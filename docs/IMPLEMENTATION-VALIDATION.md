# Implementation and validation record

Updated: 2026-09-25. This is a development build. The complete revised product plan has not passed its release gates.

## Implemented capabilities

| Area | Current behavior | Practical boundary |
|---|---|---|
| Original and import | Immutable original, SHA-256 fingerprint, page inventory, password recovery, explicit inspection failure | A failed inspection retains the original; it does not become an empty successful document |
| Resource isolation | Parsing, rendering, OCR, translation and export run in serialized child processes with Windows memory limits, cancellation and timeouts | Uploaded bytes and decoded processing are separately bounded; a small file can still exceed worker resources |
| Reading | Native text regions, raw font/text evidence, Hindi/English Tesseract alternatives, original page overlays, missing-region drawing | Per-page reading order can be corrected explicitly. Footnote relationships and cross-page semantic structure remain incomplete |
| Tables/forms | Native ruled-table proposals, explicit manual grids with uneven boundaries/merged cells and original-evidence archives, separate structure approval, form stored-value versus visible-appearance reconciliation; fingerprint/revision-bound evidence refresh | Manual grids require wholly contained untouched recognition regions, at most 200 positions, and manual transcription of every cell. Crossing scans, saved edits, adopted cells and conflicting proposals are protected. Cross-page/general correction remains incomplete. Incomplete form inventories and XFA remain unresolved |
| Durable review | SQLite checkpoints, revision conflicts, source/translation/completeness approvals, glossary precedence, manual transcription, unsaved browser text recovery | Every material change invalidates relevant reviews; human review is still required |
| Translation | Installed public native OPUS-MT models in both directions, CTranslate2 INT8 CPU inference, file/runtime guards, exact source-offset coverage, manual editing | All model outputs remain drafts. Known legal role/currency errors occur. Book-level context and bilingual quality are not qualified; IndicTrans2 is a separate optional uninstalled upgrade |
| Meaning checks | Protected numbers, uncertain legal scope, facts/roles and glossary checks require review notes | Heuristics identify review needs; they do not understand or certify all legal relationships |
| PDF exports | Readable text and adopted tables, constrained digital-text layout replacement, static original-plus-translation companion; Hindi vector appearance with a checked logical text layer | Scanned backgrounds, forms and annotations remain explicitly refused in layout replacement; overflow is blocked. Form reconciliation is available for the readable workflow |
| Export verification | Reopen/render PDF, verify every text occurrence at recorded output pages/boxes, reject missing glyphs, fingerprint artifact, approve every output page; qualification version 5 includes form-inventory/mapping and strict table-grid/member gates | Older exports, including version 4 artifacts with saved approvals, must be regenerated before final approval. Human visual review remains necessary. No pixel-perfect or universal fidelity claim |
| Other exports | DOCX merged table cells and bounded preserved crops; TXT row/column/span labels; source-page references and unresolved-issue information | DOCX/TXT remain review copies. DOCX pagination and footnote/contents relationships are not qualified |
| Cloud | Exact payload preview, single-use approval, revision/hash binding, public-content declaration, key-owner and unbilled-project checks, no paid fallback | Disabled without credentials and a current policy review; tests use mocks, not real cloud inference |
| Operation | Loopback server, explicit local UI, legacy network routes blocked, backup/checksum restore into a new directory, pinned setup scripts | Self-contained Windows installer, signing and complete offline installation bundle remain outstanding |

The manual-table editor requires the running backend to advertise its support. Older Python processes receive a save/restart instruction. A previous guarded restart was blocked before execution; by 2026-09-25 that old process had stopped independently. The normal server was then started with the tested current code, and its health and manual-table capability were verified. No user document edits or resource-limit reductions were made.

## Defects corrected during validation

- Cache eviction previously omitted pages beyond 512. Missing pages now fail explicitly.
- Legacy-font text omission, destructive OCR cleanup, speculative numbering repair, substring domain matching and fabricated reverse-cache validation were removed.
- Late results and preexisting manual regions cannot replace newer edits. Context changes invalidate sibling and cross-page approvals.
- A changed output language cannot reuse an incompatible “already target” approval.
- Windows SQLite/font handles now close on success and failure. The worker recognizes an empty error field as success.
- Local production uses the same API origin; old hosted settings cannot redirect it. Invalid runtime values fail startup.
- PDF validation exposed two distinct complex-script extraction problems. Authoring now uses pinned fpdf2/HarfBuzz and standard per-line ActualText; font coverage is checked separately. This does not substitute for rendered-page review. A subsequent PDF.js 6.3.289 check found 200 extra ampersands in a two-page, 200-occurrence Hindi fixture: PDF.js did not use ActualText. Empty/null/zero-width CMap experiments did not restore correct copied words and were not adopted. The issue was initially contained by a final-approval blocker. The next iteration uses vector outlines for generated Hindi appearance plus an invisible direct-Unicode layer. Text, dimensions, ink geometry and flat-area color are checked before publication. PDF.js now reads all 200 exact occurrences across two pages, without ampersands/null/replacement characters; first-page PDF.js rendering was visually inspected. This measures compatibility on the tested cases, not all readers/documents.
- Textarea labels, stale library status and loading/error handling for exported previews were corrected in browser tests.
- Missing legacy form evidence now has an explicit inspection/mapping workflow that preserves saved edits. Incomplete inventories and missing/duplicate evidence mappings block completeness. Export qualification version 4 prevents saved version 3 approvals from bypassing these newly enforced rules.

## Remaining work before the full plan is complete

1. Run the full 20-page local feasibility pilot and competent bilingual meaning review. The installed Marian baseline has runtime verification only. An optional IndicTrans2 upgrade needs authorized snapshots and a pinned reference runtime; upstream access requirements cannot be bypassed.
2. Implement and qualify the remaining document structure: Docling/conditional PaddleOCR, splitting recognition regions across table boundaries, correction of existing edited/adopted grids, cross-page headers/reading order/paragraphs/footnotes and many-to-many translation alignment. Native ruled-table review, bounded manual grids, static form reconciliation and explicit legacy evidence refresh are implemented within the boundaries above. Broaden the now-passing refresh checks to representative real forms; still-uninspectable fields must remain unresolved.
3. Qualify contextual glossary use during actual local inference. The current adapter translates bounded regions; glossary checks and document metadata do not themselves establish book-level context understanding.
4. Implement the remaining rich readable export structure and contents-page regeneration. Broaden the now-passing PDF.js copy/search/render fixtures to the acceptance corpus alongside independent MuPDF/Poppler checks. The vector text layer is generated only for authored pages containing Devanagari, never by modifying the uploaded original. Character selection geometry is approximate within a shaped line; search/extracted text is checked separately.
5. Assemble the document-separated 160-page development and 400-page/80-document unseen acceptance sets, with at least 500 assessed segments per language direction. Have competent bilingual reviewers score omissions, recognition, meaning, tables/forms and layout independently.
6. Measure production memory, throughput, reviewer time, crash/disk-full behavior and an actual 1,000-page workload on the target computer. Package an offline setup bundle, complete redistribution review, installer/signing and rollback qualification.

No universal accuracy percentage, legal correctness certification or full release approval is asserted by this record.
